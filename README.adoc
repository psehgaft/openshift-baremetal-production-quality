= OpenShift Bare-Metal Production Standard
:toc:
:toclevels: 2

A reusable production architecture and implementation profile for Red Hat
OpenShift Container Platform (OCP) services deployed on bare-metal
infrastructure.

== The standard

The core document is
link:OPENSHIFT_PRODUCTION_STANDARD.md[OPENSHIFT_PRODUCTION_STANDARD.md]:

* *Document ID:* OCP-BM-STD-001
* *Version:* 0.2
* *Status:* Draft for architecture and control-owner review
* *Applies to:* Production Red Hat OpenShift Container Platform services
deployed on bare-metal infrastructure
* *Review cadence:* Annually, and on material changes to the OCP release,
service scope, architecture, risk, or applicable standards

It combines a cloud reference-architecture view aligned to
ISO/IEC 22123-3:2023, an architecture description structure aligned to
ISO/IEC/IEEE 42010:2022, and a set of implementation and evidence controls
mapped to OpenShift capabilities and the surrounding service organization.

This is a standards-aligned implementation profile, not an ISO
certification or conformity assessment: conformity requires an agreed
scope, the complete applicable normative texts, documented architecture,
implemented controls, objective evidence, and assessment by the
responsible organization. Controls marked *External* cannot be completed
by configuring OpenShift alone.

The standard covers:

1. Purpose and conformance statement
2. Normative language, applicability, and control status
3. Standards register and interpretation
4. System of interest and architecture context
5. Architecture description structure aligned to ISO/IEC/IEEE 42010
6. ISO/IEC 22123-3 cloud reference architecture mapping
7. Implementation control register
8. Service Mesh / Sidecar management
9. Common OpenShift Operators
10. Minimum operational procedures
11. Production acceptance and verification
12. Project architecture description template
13. Supporting implementation standards and references
14. References

== How to use it

1. Read the standard to agree the scope, architecture, and control
register for the platform service.
2. Copy
link:ocp_baremetal_architecture_and_deployment.md[ocp_baremetal_architecture_and_deployment.md]
once per environment and replace every `{{PLACEHOLDER}}` before approval.
3. Plan the Assisted Installer deployment, record the architecture,
capture evidence, and complete the post-installation acceptance
checklists in the copied record.
4. Store the final, approved record with the change and installation
evidence.

== Build and preview the documentation site

Prerequisites: `git`, Node.js, and the Gulp CLI (`npm install -g gulp-cli`).

[source,console]
----
npm install
npx gulp
----

The preview is served at http://localhost:3000 while the command runs.
To build the static site into `gh-pages/` instead, run:

[source,console]
----
./site.sh
----

On every push to `main`, the `.github/workflows/docs.yml` workflow builds
the Antora site and deploys it to the `gh-pages` branch for GitHub Pages.
